# 修炼系统

Game Service 负责修为数值、容量、功法资格、会话计时、境界转换、突破概率、惩罚和
持久化。Paper 只提交玩家选择并展示权威结果。

## 玩家流程

```text
可获得奖励的 MythicMob 击杀
  -> 未炼化修为储备
  -> 闭关时选择启用中的功法和修炼区域
  -> 保留的投入量提升已炼化修为和功法层数
  -> 按配置进行突破，消耗丹药并结算境界转换
```

未炼化修为储备与已炼化修为是两种不同资源。击杀怪物绝不会直接提升功法或境界。

## 境界目录

权威的 22 级境界目录位于：

```text
game-service/src/immortal_mmo/cultivation/realm_catalog.json
```

当前分组如下：

- 1-13 级：练气各层；
- 14-16 级：筑基；
- 17-19 级：结丹；
- 20-22 级：元婴。

每个等级都定义了 `max_exp` 及其准确的后继等级。修改内容后需要重启 Game Service，
并且必须保持 ID 和转换关系一致。

## 功法与层数

功法定义位于：

```text
game-service/src/immortal_mmo/cultivation/techniques.json
```

重要字段包括稳定的 `technique_id`、展示元数据、分组、大境界、时间权重、最高层数、
元素要求、最低等级、前置条件、装备要求、分类和效果数据。

`invested_amount` 是可审计的规范余额。`current_layer` 是在事务中维护的投影，供
API、GUI 和任务目标使用。其范围为 0 到 13，并会随增加和减少同步更新。0 点投入
对应 0 层；玩家必须投入完整的第一段成本后才会进入 1 层，因此 0 层不产生功法效果。

完整曲线包含从 0 层到 13 层的 13 段正整数成本。为了保留原有 1 至 13 层的每段成长
成本，新增的 0 -> 1 段完整复制原 1 -> 2 段，所以 0 -> 1 与 1 -> 2 成本相同。练气
普通功法的准确曲线如下：

| 目标层数 | 本段成本 | 累计投入 |
|---:|---:|---:|
| 1 | 15 | 15 |
| 2 | 15 | 30 |
| 3 | 22 | 52 |
| 4 | 33 | 85 |
| 5 | 49 | 134 |
| 6 | 74 | 208 |
| 7 | 111 | 319 |
| 8 | 166 | 485 |
| 9 | 250 | 735 |
| 10 | 375 | 1,110 |
| 11 | 562 | 1,672 |
| 12 | 843 | 2,515 |
| 13 | 1,265 | 3,780 |

因此一门练气普通功法满层需要 3,780 点投入，三门满层合计 11,340 点。练气十层的
累计境界门槛仍为 11,293 点，三门满层只是在原有“至少覆盖门槛”的规则上多出 47 点
余量。筑基、结丹和元婴功法分别使用原有的 `17:10`、`9:5`、`2:1` 增长倍率，并遵循
同一条最终曲线规则：复制第一段作为入门段，保留后续每段成本，同时扩展单门满层容量。
这些比例只描述各层成本曲线的增长，不是闭关速度倍率。

这次曲线扩展不会修改 1 至 22 级境界目录、任何 `max_exp`、累计境界阈值或突破规则；
变化仅限功法从 0 层开始，以及新增入门段后增加的功法满层容量。

当前限制：功法目录已经存在，但面向玩家的功法学习/获取流程尚未完成。在内容或未来
的学习功能创建已学功法之前，普通玩家的闭关 GUI 可能为空。

## 闭关

玩家命令：

```text
/immortal seclusion
```

GUI 会加载权威的已学功法。每次提交需选择 1-5 门符合以下条件的功法：

- 处于启用状态；
- 尚未满层；
- 使用相同的 `group_code`；
- 满层容量完全相同；
- 符合当前玩家和内容状态的资格要求。

GUI 当前最多显示前 45 门已学功法。

玩家必须位于 Paper 配置的修炼长方体区域内，且该区域的 `area-id` 必须存在于
`areas.json`。Paper 只发送语义 ID；Game Service 负责解析速度和产出基点。

### 十秒炼化周期

普通闭关每 10 秒产生一个离散炼化周期。练气、筑基、结丹和元婴原有的 10、20、50、
100 小时满层估算只用于推导基础速度，不是玩家必须等待的闭关时长。一个会话选多少门
功法都不会提高总炼化速度；产生的总量会在所选功法之间平均分配，并在某门满层后转给
仍有容量的功法。

基础周期速度由所选功法组自身的满层容量和大境界估时计算。高境界玩家修炼低境界功法
时，再使用大境界寿命权重比作为速度倍率：

| 大境界 | 速度权重 |
|---|---:|
| 练气 | 1 |
| 筑基 | 2 |
| 结丹 | 5 |
| 元婴 | 10 |

同境界修炼为 1 倍；筑基修炼练气为 `2/1 = 2` 倍，结丹修炼筑基为 `5/2` 倍，元婴
修炼筑基为 `10/2 = 5` 倍，元婴修炼结丹为 `10/5 = 2` 倍。这是速度倍率，不会修改
功法容量、层数成本或修为价值。区域的 `speed_basis_points` 继续叠乘速度，
`yield_basis_points` 控制消耗未炼化储备后实际保留的投入。

不足 10 秒不会产生修为；10 秒产生一个完整周期，25 秒产生两个。服务器延迟或玩家
离线后可以一次追赶多个完整周期，分段结算与一次合并结算的最终消耗和逐门投入相同。
普通闭关响应中的 `completes_at` 只表示首次可结算时间，不是预计满层时间。Paper 在开始
后及每次 `active` 结算后都等待 200 ticks 再调用权威结算；中间的 `active` 周期只刷新
修为投影，不向聊天栏重复发送结算消息。

当仍有储备或容量可以处理时，结算可以保持 `active`，Paper 会继续安排下一次权威结算，
而不会错误地宣告完成。

Paper 重启后，其自动结算计时器目前不会恢复。Game Service 会话仍会持久化，但在
实现重启恢复之前，运维人员或开发者可能需要通过 API 触发恢复。

## 修炼区域

Game Service 目录示例：

```json
{
  "area_id": "accelerated_cave",
  "name": "加速洞府",
  "version": 1,
  "speed_basis_points": 20000,
  "yield_basis_points": 10000
}
```

Paper 映射示例：

```yaml
cultivation:
  areas:
    - area-id: accelerated_cave
      world: world
      min: {x: 100, y: 20, z: 100}
      max: {x: 132, y: 80, z: 132}
```

两端必须使用完全相同的 `area_id`。同一世界中的 Paper 长方体区域不得重叠。

## 突破

玩家命令：

```text
/immortal breakthrough <pill-count>
```

当前突破目录实现了 `qi_to_foundation`：来源等级为 10-13，目标等级为 14。开始时
会消耗 `foundation_pill`，并在冻结的持续时间结束后结算。

当前概率配置：

- 一至三灵根：一颗丹药必定成功；
- 四灵根：使用明确的 1-10 颗丹药概率表；
- 五灵根：使用另一份明确的 1-10 颗丹药概率表。

失败策略可能使玩家在练气后期内推进，也可能扣减功法投入量；准确结果会被冻结并
持久化，因此重试或重启无法重新随机结果。

向已完成初始化的在线玩家发放测试丹药：

```text
/immortal cultivation grant-item <player> foundation_pill <count>
```

当前调整端点只接受 `foundation_pill`，数量范围为 1-1,000,000。

## 功法变更 API

Game Service 提供权威的放弃和转移操作。这些操作可能降低投入量/层数、已炼化修为和
启用中的境界历史。目前尚无可供玩家执行这些操作的完整 Paper 命令。

## 任务集成

- 物品目标会重新读取权威的丹药/物品堆叠；
- 功法目标会读取指定启用功法的当前层数；
- 境界目标会读取当前绝对等级；
- 相关的物品、闭关、变更和突破结果会刷新正在追踪的任务。

交付任务前，状态目标可能因倒退或放弃而再次变为未完成。参见[任务系统](quests.md)。

## 故障排查

- GUI 为空：玩家没有已学且符合条件的功法。
- 未知区域：Paper 的 `area-id` 不存在于 Game Service 目录中。
- 混合境界选择：只能选择属于同一大境界的功法。
- 突破物品不足：发放 `foundation_pill` 或修正物品堆叠；事务会安全回滚。
- 会话冲突：当前人生已有一个待处理或启用中的修炼会话，或者同一个幂等键被用于
  不同输入。
