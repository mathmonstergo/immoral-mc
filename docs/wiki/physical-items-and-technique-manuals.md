# 实体物品与功法秘籍

ImmortalMC 的可交付自定义物品使用稳定的 `item_instance_id`。Game Service 保存物品实例、
当前人生、状态和位置；Paper 背包中的物品只是权威实例的显示载体，不以名称、Lore 或原版
堆叠数量作为身份。

## 当前获取方式

当前随包任务 `first-steps` 完成后会奖励：

- 1 本 `technique_manual:GF_YinqiShu_01`，对应功法 `GF_YinqiShu_01`；
- 50 点固定未炼化修为。

实体物品模型可以被后续怪物掉落、合成和其他任务奖励复用，但当前 Wiki 不把尚未接入的
怪物掉落或合成配方描述为已开放玩法。

## 投递与对账

固定物品奖励先创建为 `pending_delivery`。Paper 在玩家登录和相关物品操作后读取待投递列表
与权威背包列表，然后执行以下对账：

- 同一 `item_instance_id` 在背包中最多保留一份；
- 已消耗或已存入仓库的实例会从玩家背包移除；
- 权威位置为 `inventory`、但客户端缺失的实例会被恢复；
- 待投递实例成功放入背包后，Paper 向 Game Service 确认投递；
- 背包已满时保留待投递状态，不会把物品丢在世界中或改成本地临时奖励。

Game Service 不可用时，Paper 不会伪造物品实例。服务恢复后重新登录或触发对账即可继续。

## 使用功法秘籍

手持实体功法秘籍并右键即可研读。Paper 只提交秘籍的 `item_instance_id` 和稳定幂等操作 ID；
Game Service 校验当前人生、实例归属、背包位置、秘籍中的功法 ID 和功法目录，然后原子完成：

1. 把秘籍实例标记为已消耗；
2. 为当前人生创建对应功法；
3. 将功法初始层数设为第 0 层；
4. 冻结响应，使相同操作重试不会重复学习或重复消耗。

成功后，功法会出现在闭关 GUI 和任务功法目标的权威投影中。已经学会该功法、实例不属于
当前人生、实例不在背包或秘籍数据无效时，操作会失败并重新对账背包。

## 任务交付

任务交付只接受 Paper 从玩家实际背包扫描到的实体 `item_instance_id` 列表。Game Service 会
重新校验这些实例属于当前人生、状态为 `owned`、位置为 `inventory`，再按任务要求选择并
一次性消耗。玩家仅持有同名原版物品、伪造名称/Lore 或提交仓库中的实例都不能完成交付。

## 地区仓库

实体物品可通过[地区仓库](regional-storage.md)存取。存入后权威位置变为 `storage`，取出后
变回 `inventory`；功法秘籍的实例 ID 和功法信息不会变化。

## 当前限制

- 实体物品当前不可与普通原版物品合并成可信堆叠；一个实例代表一个可追踪物品；
- 当前没有玩家命令用于任意生成实体物品；内容来源由 Game Service 玩法流程创建；
- 怪物实体物品掉落和合成配方尚未作为公开玩法交付；
- 未炼化修为奖励不受地区、境界或修炼倍率加成；VIP 奖励倍率尚未实现。

## 故障排查

- 奖励未出现：确认背包有空位，并检查 Game Service 与 Paper 日志中的
  `physical_item_reconcile_failed`；
- 秘籍右键无反应：确认物品是带有效实例身份的实体秘籍，而不是同名原版书；
- 秘籍提示研读失败：不要手工复制物品，重新登录触发权威对账；
- 仓库取出后又消失：检查该实例是否已被任务交付或秘籍学习消耗，并以 Game Service 状态为准。
