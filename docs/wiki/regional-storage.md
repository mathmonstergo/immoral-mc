# 地区仓库

地区仓库为当前人生提供按 `area_id` 隔离的持久物品空间。Game Service 保存权威槽位、
物品实例和修订版本；Paper 只根据当前坐标解析地区并显示大箱子界面。

## 玩家使用

玩家必须位于已经配置的地区中，然后执行：

```text
/immortal storage
```

界面使用 54 格大箱子：

- 前 45 格存放物品；
- 最后一行显示上一页、刷新、地区/页码/修订状态、关闭和下一页按钮；
- 每个地区默认提供 9 页，共 405 个物品槽；
- 不同 `area_id` 的内容完全隔离；同一账号的不同人生也不会共用仓库。

页面切换会重新读取权威快照。仓库内容在 PostgreSQL 中持久化，Paper 重启不会清空。

操作方式：

- 点击玩家背包中的实体物品：存入当前页第一个空槽；
- 左键仓库物品：取回玩家背包；
- 右键仓库物品：选中移动来源，再点击另一个物品槽执行移动或原子交换；
- 点击刷新：重新读取当前页；
- 玩家离开地区、切换世界、当前人生变化或权限失效时，界面会关闭。

## 地区与容量

Paper 使用 `cultivation.areas` 中的长方体配置解析当前 `area-id`；Game Service 使用
同一个稳定 ID 校验仓库目录。不要用世界名称、展示名称或坐标字符串替代 `area_id`。

当前默认目录为每个已知地区提供：

```text
page_count: 9
item_slots_per_page: 45
```

仓库容量属于服务端内容规则，不受境界、修炼速度、区域收益或 VIP 倍率影响。

## 实体物品

ImmortalMC 自定义物品带有稳定的 `item_instance_id`。仓库存取移动的是这个权威实例，
不是只匹配物品名称或 Lore。功法秘籍存入仓库后仍保留其准确功法和实例身份，取出后可以
正常使用。

玩家背包、Paper GUI 和 PostgreSQL 不能共享单个数据库事务，因此所有仓库操作都使用
幂等操作标识和修订版本。发生超时、冲突或过期页面时，界面会重新加载，而不会猜测哪一
边的数据正确。

## 限制

- 当前只支持玩家本人、当前人生、当前所在地区；
- 不支持跨地区远程访问、账号共享、宗门共享、自动整理、搜索或一键存取；
- 玩家背包没有空间时，取出操作不会删除仓库中的物品；
- 地区未配置或 Game Service 不可用时不会创建 Paper 本地备用仓库。

## 故障排查

- `当前不在可用仓库地区`：检查玩家坐标是否落在 `cultivation.areas` 的长方体内；
- `未知地区仓库`：确认 Paper 的 `area-id` 与 Game Service 目录完全一致；
- `仓库状态已变化`：关闭或刷新界面后重试，禁止复制旧页面中的物品；
- 页面为空：确认当前人生和当前地区是否正确，不同地区的内容不会互通。
